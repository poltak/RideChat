# RideChat protocol version 1

This document defines the Android core wire values used by the transport worker. The transport supplies one complete control payload or a byte stream carrying length-delimited audio frames. The core does not open sockets and does not know about Nearby callbacks.

All integer fields use network byte order (big-endian). Text is UTF-8. A decoder rejects an unknown version, an unknown type, invalid UTF-8, a length outside its bound, a truncated value, or any trailing byte.

## Limits

- Protocol version: `1`.
- A complete control payload is at most 8,192 bytes.
- An Opus payload is non-empty and at most 2,048 bytes. The encoded audio envelope has a small header and can therefore be larger than the Opus payload limit.
- Ride ID: non-empty, no NUL, at most 64 UTF-8 bytes.
- Sender/member ID: non-empty, no NUL, at most 64 UTF-8 bytes.
- A member list has one to four unique IDs.
- A Nearby raw authentication token is non-empty and at most 256 bytes.
- Resume secrets, nonces, and HMAC proofs are exactly 32 bytes.

The Kotlin codec applies all limits before copying a declared value. This keeps malformed input from causing an unbounded allocation.

## Control payloads

Every control payload starts with:

```text
u8 version = 1
u8 type
```

The type values are:

| Type | Name | Body |
| ---: | --- | --- |
| 1 | `HELLO` | `text rideId`, `text senderId` |
| 2 | `WELCOME` | `text rideId`, `text senderId`, `bytes[32] resumeSecret` |
| 3 | `MEMBERS` | `text rideId`, `u8 count`, `count × text memberId` |
| 4 | `READY` | `text rideId`, `text senderId` |
| 5 | `MUTE` | `text rideId`, `text senderId`, `u8 muted` (`0` or `1`) |
| 6 | `PING` | `i64 nonce` |
| 7 | `PONG` | `i64 nonce` |
| 8 | `RESUME_HELLO` | `text rideId`, `text senderId`, `bytes[32] nonce`, `u8 role`, `bytes sessionToken` |
| 9 | `CHALLENGE` | same fields as `RESUME_HELLO` |
| 10 | `PROOF` | `text rideId`, `text senderId`, `bytes[32] nonce`, `bytes[32] proof`, `u8 role`, `bytes sessionToken` |
| 11 | `ACCEPTED` | `text rideId`, `text senderId` |
| 12 | `LEAVE` | `text rideId`, `text senderId` |
| 13 | `END` | `text rideId` |

`text` and variable `bytes` values are encoded as `u16 byteLength` followed by exactly that many bytes. The role byte is `0` for `HOST` and `1` for `MEMBER`. A proof's nonce is the nonce generated by the proof sender; the receiver pairs it with the peer nonce it stored during the challenge exchange.

`WELCOME.resumeSecret` is transferred only after the Nearby authentication digits have been shown and explicitly confirmed. Keep it in memory for the current ride. It must never be advertised, logged, or sent through the resume path.

## Audio stream framing

Audio is a stream, so one read can contain a partial frame, one frame, or multiple frames. Each frame is:

```text
u32 bodyLength
u8 version = 1
u8 kind = 1 (OPUS)
text rideId
text senderId
i64 generation
i64 sequence
i64 sampleTime
bytes opusPayload
```

`bodyLength` counts every byte after the four-byte length prefix. The body length is bounded by the implementation's fixed frame bound before the body is copied. `generation`, `sequence`, and `sampleTime` are non-negative. `sampleTime` is in the 48 kHz media clock (960 samples per 20 ms frame); it is not a phone wall-clock timestamp. The sender increments `sequence` within a stream generation and changes `generation` after reconnect or stream reset.

The receiver must authenticate the connection and match the ride, sender, and generation before playback. The host forwards an accepted encoded frame to every member except the source sender. A client cannot choose another sender ID in the envelope.

## Resume authentication

After first admission, a member and host retain a random 32-byte pair secret. A resume proof is HMAC-SHA256 over the following canonical, length-delimited sequence:

```text
ASCII "ridechat-resume-v1"
u8 protocolVersion
text rideId
text localMemberId
text remoteMemberId
u8 role
bytes localNonce[32]
bytes remoteNonce[32]
bytes sessionToken
```

The key is the pair secret. The role, both member IDs, both fresh nonces, ride ID, protocol version, and the raw Nearby authentication token are all bound to the proof. Use fresh random nonces for every attempt. Compare received proofs with a constant-time comparison and reject a nonce already accepted for the same resume context. A missing secret never enters the unattended resume path; it requires the visible join flow again.

## Jitter and mixing rules

The core keeps one bounded queue per remote speaker. It waits for three 20 ms frames (60 ms) before starting playout and stores at most six frames. It accepts a higher generation by clearing the old queue; lower generations, duplicate sequences, and sequences older than the next playout slot are rejected. When a full queue receives a newer frame, it evicts its oldest retained frame and advances the playout cursor to the earliest retained sequence. Every due 20 ms slot advances even when its frame is missing, and the queue returns `null` for that slot so the audio layer can request Opus concealment or emit silence. The preferred `poll()` API advances one slot per call, so the output loop supplies the cadence. The timestamp overload is only for a caller that has mapped the remote media clock to its local clock. A reconnect starts with an empty queue.

The mixer adds signed 16-bit PCM samples and saturates each result to `[-32768, 32767]`. The host does not decode and re-encode a relayed frame. It validates the authenticated source connection, ride ID, sender ID, generation, sequence, and payload bound before enqueueing it, and never sends the frame back to its source.
